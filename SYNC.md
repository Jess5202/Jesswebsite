# Owner-managed inventory

NextSix automation is paused. Do not run the old import script or overwrite owner-managed inventory. The public website uses `/api/listings`; the owner manages records at `/admin`. Records and uploaded image files are stored durably in the logical R2 binding `BUCKET`. The catalog is a versioned JSON document (`property-manager/catalog-v1.json`) with conditional writes; browser storage is used only for language preference. Existing published inventory is retained as `web/seed.json` until the first owner mutation persists the catalog.

Server-side owner access requires trusted Sites identity headers and the owner's verified email. Every mutation also validates same-origin requests; stale revisions are rejected to avoid overwriting changes from another tab. Draft/archived records are excluded from the public API. Do not change the Site audience when deploying. No passwords, access tokens or credentials belong in the HTML, repo or storage catalog.

Edit `web/index.html`, `web/admin.html` and `worker/index.js`. Run `node scripts/build.mjs`, `node scripts/validate-artifact.mjs` and `node tests/worker.test.mjs`. The build embeds both pages and initial seed inventory into `dist/server/index.js`; package the root `.openai/hosting.json` plus `dist/server/` (retaining that path) for Sites Worker deployment; the verified entrypoint is `dist/server/index.js`. No standalone assets, dependency installation or framework are required. Use the same retained Site ID and source repository.

The admin copy-paste workflow uses `web/parse-property-copy.mjs`, embedded during build. It proposes fields without saving or publishing. Preserve full copy as description; never confuse bank value/maintenance fee with the sale price, or land dimensions with built-up area. Owner reviews fields and uploads photos before saving. Listing `reference` is optional (e.g. JS3128).

Property search combines type, location, price bounds, minimum bedrooms, tenure and all selected features. Shared pure logic lives in `web/property-filters.mjs`, embedded into frontend, admin copy parser and Worker at build time. Preserve explicit owner `features` arrays, including empty arrays; only records with no features field infer conservative tags from their existing text. No inferred tags are written back without an owner save. Run `node tests/property-filters.test.mjs` along with the other checks.
